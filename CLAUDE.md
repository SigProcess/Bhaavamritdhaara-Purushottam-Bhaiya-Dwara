# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- **Dev server**: `npm run dev` (Vite, serves at http://localhost:5173)
- **Build**: `npm run build` (outputs to `dist/`)
- **Preview build**: `npm run preview`

No test runner or linter is configured.

## Deployment

Deployed via Netlify. Push to `main` triggers a deploy. Config is in `netlify.toml`.

## Architecture

React 18 + Vite SPA. No router — single page. All styling is in one CSS file (`src/App.css`) using CSS variables. No CSS modules or preprocessors.

### Data flow

All playlist/collection data lives in `src/data/playlists.json`. The JSON has two top-level keys:
- `collections`: Array of collection objects, each containing a `playlists` array of sub-playlists
- `playlists`: Array of standalone playlists not in any collection

Each playlist has `id`, `title`, `url` (YouTube playlist link), and `thumb` (YouTube thumbnail URL derived from the first video in the playlist).

To add/reorganize playlists, edit the JSON only — no component changes needed.

### Component hierarchy

`App` → `Nav`, `Hero`, `PlaylistSections`, `Footer`

`PlaylistSections` is the main content area: it renders `CollectionCardButton` cards in a grid. Clicking a collection or playlist opens a fullscreen `YouTubeLightbox` overlay. Collections show a grid of sub-playlists; selecting one shows an embedded YouTube player with a scrollable video list below. Standalone playlists open directly to the player view.

### Static assets

Images and video are in `public/` (`bhaiya-portrait.jpg`, `bhaiya-altar.jpg`, `bg-video.mp4`, `favicon.svg`). Referenced via absolute paths (e.g., `/bhaiya-portrait.jpg`).

### Playlist video data

Video IDs and titles for all playlists are pre-fetched and stored in `src/data/playlistVideos.json`, keyed by YouTube playlist ID (the `list` query param). To refresh: `npm run fetch:playlists` (uses yt-dlp). Pass `--force` to re-fetch all. Run this after adding new playlists to `playlists.json`.

### Hindi transcripts

Transcripts of the **discourse** videos (pravachan, lekh, vishleshan, dhvani) are
generated by `scripts/transcribe-videos.js`. Bhajan (sung) playlists are excluded.
Full runbook: `docs/transcripts.md`.

```
npm run transcribe:setup      # one-time: fresh yt-dlp + local Whisper
npm run transcribe:probe      # build transcripts/catalog.json (durations + discourse/bhajan)
npm run transcribe:captions   # fast pass: videos that have hi-orig captions
npm run transcribe:whisper    # slow pass: the ones that don't (~8x realtime)
npm run transcribe:edits      # fold hand-corrections back in
npm run transcribe -- --limit 5 --dry-run
```

Prefer the two separate passes over bare `npm run transcribe`: in `auto` mode one
caption-less hour-long talk blocks the queue for ~8 minutes of local ASR.

Two sources, tried in that order:

1. **captions** — YouTube's own `hi-orig` auto-caption track. Every discourse
   sampled so far has one, it is already Devanagari, and it costs one small
   download. A bare `hi` track *without* `hi-orig` is a machine translation of a
   mis-detected language (YouTube reads these bhajans as Romanian) and is ignored.
2. **whisper** — local ASR via `scripts/whisper-worker.py`, used only when a
   discourse has no original Hindi track. Roughly 8× realtime on an M2 Pro.
   Tune domain vocabulary in `scripts/hindi-prompt.txt`; it is fed to Whisper as
   the initial prompt so Pranami terms and names come out right.

Useful flags: `--source captions|whisper`, `--playlist <title substring>`,
`--video <id>`, `--limit N`, `--min-minutes`/`--max-minutes`, `--force`,
`--keep-audio`, `--model <hf repo>`.

Output per video, under `transcripts/`:
- `text/<playlist>/<title>--<id>.txt` — paragraphed reading copy
- `srt/<playlist>/<title>--<id>.srt` — subtitles
- `data/<playlist>/<title>--<id>.json` — segments plus metadata
- `index.json` — manifest of everything transcribed; also the resume marker, so
  re-running only picks up what is missing

`transcripts/.audio/` is scratch space (deleted per video unless `--keep-audio`).

**Manual corrections.** Edit the `.txt` (prose, punctuation — timings untouched)
or the `.srt` (lines and timings — reading copy regenerated from it), then run
`npm run transcribe:edits` (`scripts/apply-transcript-edits.js`). Edits are
detected by content hash, so re-running is harmless. Applied edits mark the
transcript `reviewed`, which excludes it from `--force` unless `--force-reviewed`
is also passed. Don't run a transcription pass and `transcribe:edits` at the same
time — both write `transcripts/index.json`.

**yt-dlp version matters.** YouTube returns HTTP 403 on audio streams for yt-dlp
releases more than a few months old, and the Homebrew formula lags. The scripts
prefer `.venv-transcribe/bin/yt-dlp` when it exists; refresh it with
`npm run transcribe:setup`.

### Thumbnail convention

Thumbnails use `https://img.youtube.com/vi/{VIDEO_ID}/mqdefault.jpg`. When adding a new playlist, get the first video ID with: `yt-dlp --flat-playlist --print id --playlist-items 1 "PLAYLIST_URL"` and add the thumb URL to the JSON entry.

# Coding Learning Mode

I am using Claude Code not only to complete tasks, but also to improve my coding skills.

## Core principle

Act as a pair programmer and coding teacher, not just a code generator.

When making meaningful code changes, explain what you are doing, why you are doing it, and what I can learn from it.

Do NOT explain trivial commands such as `ls`, `pwd`, `cd`, simple file searches, or routine tool operations unless they are relevant to learning.
